# E-Commerce Sales & Customer Analytics

An end-to-end analyst project: raw data → Python cleaning → MySQL → SQL
analysis → Python EDA → Power BI dashboard → business recommendations.
Built to demonstrate the full analyst workflow, not just a dashboard.

## Business Problem

An e-commerce company wants to understand what's driving (and holding back)
revenue: which customers and products matter most, whether its discounting
strategy is actually working, and where to focus retention effort.

## Objectives

- Build a clean, normalized relational data model from raw transaction data
- Answer sales, customer, and product questions using SQL (including window
  functions and CTEs)
- Segment customers using RFM (Recency, Frequency, Monetary) analysis
- Quantify the revenue/margin trade-off of the discounting strategy
- Present findings in an interactive Power BI dashboard
- Turn the analysis into concrete, actionable business recommendations

## Dataset

A realistic, internally-consistent synthetic dataset generated by
`src/generate_data.py` (5,000 customers · 800 products · 25,000 orders ·
~54,000 order line items) — deliberately seeded with the kind of messiness
real transactional data has (nulls, duplicates, sign errors, orphaned
records) so the cleaning phase is real work, not a formality. Counts are
config values at the top of the script — bump them up to 20,000 /
2,000 / 100,000+ if you want a larger dataset.

## Data Model

```
CUSTOMERS ─1──N─ ORDERS ─1──N─ ORDER_ITEMS ─N──1─ PRODUCTS
```

Orders and order items are kept as separate tables (rather than one wide
orders table) so the schema is normalized — this avoids repeating customer/
order data per line item and is the detail worth explaining in an interview
when asked "why did you design it this way?"

See `sql/01_database_schema.sql` for full DDL.

## How to Run This Project

```bash
pip install -r requirements.txt

# 1. Generate the raw dataset
python src/generate_data.py

# 2. Clean it
python src/data_cleaning.py

# 3. Load into MySQL (edit src/database.py with your DB credentials first)
mysql -u root -p < sql/01_database_schema.sql
python src/database.py
mysql -u root -p ecommerce_analytics < sql/02_data_quality.sql

# 4. Run the SQL analysis
mysql -u root -p ecommerce_analytics < sql/03_sales_analysis.sql
mysql -u root -p ecommerce_analytics < sql/04_customer_analysis.sql
mysql -u root -p ecommerce_analytics < sql/05_product_analysis.sql
mysql -u root -p ecommerce_analytics < sql/06_advanced_analysis.sql

# 5. Python EDA (already executed once with outputs saved -- re-run to refresh)
jupyter notebook notebooks/02_eda.ipynb

# 6. Power BI dashboard
# Open Power BI Desktop, follow dashboard/DAX_measures_and_model.md
```

## SQL Analysis Highlights

40 queries across four files, organized basic → intermediate → advanced,
including window functions (`RANK`, `DENSE_RANK`, `ROW_NUMBER`, `NTILE`,
`LAG`, `PERCENT_RANK`, running `SUM() OVER()`), CTEs, and a full RFM
segmentation query. See `sql/06_advanced_analysis.sql` for the RFM scoring
logic — that's the query most worth walking an interviewer through.

## Key Business Insights

Full detail with numbers in [`reports/business_insights.md`](reports/business_insights.md). Headlines:

1. **Discounting is eroding margin without a clear volume payoff** — full-price orders have both the highest volume and the best margin (31.6%); margin falls in a straight line to 9% at the 25% discount tier while unit volume barely moves.
2. **Revenue is concentrated** — 40.4% of customers generate ~80% of revenue.
3. **RFM segmentation** — "Champions" (22.6% of customers) spend ~9.6x more on average than "Lost Customers" (25.5% of customers).

## Recommendations

1. Cap standard promotional discounts around 10%; reserve deeper discounts for genuine clearance.
2. Shift retention budget toward the top 40% of customers by spend.
3. Launch a targeted win-back/loyalty nudge for "Potential Loyalists" and "At Risk" segments.
4. Track category-level profit margin alongside revenue, not revenue alone.
5. Monitor the Pareto ratio over time as a customer-base health metric.

## Interview Talking Points

- **Why separate `orders` and `order_items`?** Normalization — avoids
  repeating customer/date info per line item, and correctly models the
  one-to-many relationship between an order and its products.
- **Why classify missing values instead of dropping rows?** Dropping a
  customer with a missing `gender` would also delete their real orders and
  revenue — classifying as `'Unknown'` preserves the transaction while being
  honest about the gap.
- **What does the RFM query actually compute?** Recency/Frequency/Monetary
  per customer, each bucketed into quintiles via `NTILE(5)`, combined into a
  0–15 score, then mapped to a named segment via a `CASE` statement.
- **What's the single most interesting finding?** The discount-vs-margin
  relationship: it directly challenges the assumption that "more discount →
  more revenue" and shows a case where the data argues against something
  that looks intuitively true.
